# Customer Journey Atlas

고객 여정 도식화 · Amplitude/Braze/GA4 태깅 · CRM 캠페인을 한 화면에서 관리하는 단일 파일 웹 도구.

## 화면 구성

| 영역 | 역할 |
| --- | --- |
| 보드 드롭다운 | 여정 지도를 여러 판으로 나눠 관리. 추가·이름변경·복제·삭제. 태그·캠페인 목록은 모든 보드를 합쳐서 보여준다(JSON 내보내기/불러오기는 상단 폴더 아이콘의 전체 문서 단위 기능으로 통합했다) |
| 상단 캔버스 | 페이지 노드 배치·연결. 곡선/직각/직선 경로, 실선·점선, 단방향·양방향, 색·굵기, 연결점 지정, 경로 직접 수정, 자석 정렬, 자동 정렬 |
| 노드 카드 | 배지는 플랫폼별(Amplitude/Braze/GA4) 태그 수와 CRM 캠페인 수만 센다. 캠페인은 아래에 채널 아이콘·이름·상태점으로도 표시(상세). `상세/간단` 토글로 접을 수 있다. 카드마다 색·크기·모서리 모양 지정 |
| 중앙 스테이지 | 선택한 페이지의 화면 이미지를 크게 보고 사각형·원·화살표·텍스트·펜·이미지 레이어를 직접 그림 |
| 좌측 패널 | CRM 캠페인 등록/수정/삭제, 선택한 레이어에 캠페인 연결(연결 시 화면에 번호 핀 표시) |
| 우측 패널 | 태깅 설정 등록/수정/삭제 — 플랫폼·이벤트명·트리거·셀렉터·전송 속성·적용 상태 |
| 태그 목록 탭 | 전체 페이지의 태그를 플랫폼/페이지/상태/검색어로 필터, CSV 내보내기 |
| 캠페인 탭 | 전체 캠페인을 채널/상태/검색어로 필터, 어느 화면에 붙었는지 표시, CSV 내보내기 |
| 앨범 탭 | Cloudinary로 변환된 이미지를 태그(페이지)별로 모아보기. 보드·태그·검색어·업로드일순으로 필터링, 카드 클릭 시 해당 페이지로 이동 |

좌·우 패널 머리의 `확장` 버튼을 누르면 그 패널이 **아래 영역 전체(가로 끝에서 끝)** 를 혼자 쓰고, 위쪽 여정 지도는 140px로 줄어 페이지 전환만 남는다. 넓어진 폭에 맞춰 카드가 여러 열로 흐른다. 좌·우 중 하나만 확장되며(다시 누르면 원래대로), 이 설정은 문서가 아니라 브라우저에만 기억된다.

경계선(가로 1개, 세로 2개)을 드래그하면 각 영역 크기가 바뀌고, 스테이지는 `맞춤` 모드에서 영역 크기에 맞춰 자동으로 배율을 다시 계산한다. 확대/축소 버튼으로 수동 배율도 가능하다.

## 연결선 (화살표)

| 설정 | 값 |
| --- | --- |
| 경로 | 곡선 · 직각 · 직선 |
| 선 | 실선 · 점선 / 가늘게 · 보통 · 굵게 |
| 화살표 | 단방향 · 양방향 · 없음 |
| 색 | 기본 · 파랑 · 보라 · 초록 · 주황 · 빨강 · 회색 |
| 연결점 | 출발·도착 각각 자동 / 위 / 오른쪽 / 아래 / 왼쪽 |
| 경로 수정 | 선 위의 반투명 점을 끌면 꺾임점이 생기고, 꺾임점을 끌어 옮기거나 더블클릭해 지운다. `경로 초기화`로 되돌림 |

연결선을 클릭하면 위 설정 팝오버가 열린다. 기본 곡선은 연결점의 바깥 방향으로 빠져나가도록 그려져 노드에 파고들지 않는다.

## 배치 도구

- **자석 정렬**(툴바 자석 버튼): 다른 페이지의 좌·중앙·우, 상·중앙·하 선에 7px 안에서 달라붙고 안내선이 표시된다. 끄면 22px 격자에만 맞춰진다.
- **자동 정렬**: 흐름 순서(연결 방향)대로 계층을 만들어 다시 세운다. **화면 배율·위치는 건드리지 않고**, 정렬 전 위치를 기준점으로 삼아 원래 있던 자리 근처에 배치하므로 시야가 튀지 않는다. 결과가 마음에 들지 않으면 토스트의 `되돌리기`를 누른다.

## 로그인 · 권한 (두 가지 방식)

| 방식 | 쓰는 곳 | 강제력 |
| --- | --- | --- |
| **구글 로그인 + 역할** (서버관리자/운영자/일반회원) | Supabase를 연결해 배포한 사이트 | 서버(RLS)에서 강제 — 브라우저를 고쳐도 안 뚫림 |
| **관리자 비밀번호** | Artifact 링크·로컬 파일·드라이브 폴더 | 화면 수준 편집 잠금 |

Supabase가 연결되면 비밀번호 잠금 버튼은 사라지고 로그인 버튼이 나타납니다. 설정은 [DEPLOY.md](DEPLOY.md) 참고.

회원 · 권한 관리 화면(구글 계정 메뉴 → `회원 · 권한`)에서 이름·이메일·등급으로 검색할 수 있습니다. 저장 위치 화면의 "서버 (Supabase)" 연결 항목은 서버관리자에게만 보입니다.

## 관리자 모드(비밀번호)

- 자물쇠 버튼으로 **관리자 비밀번호**를 설정하면, 비밀번호를 아는 사람만 추가·수정·삭제할 수 있고 나머지는 보기 전용이 된다(편집 버튼·포트·도구가 숨겨지고 노드 이동도 막힌다).
- 저장되는 값은 평문이 아니라 **임의 salt + PBKDF2-SHA256 20만 회 해시**다. JSON을 열어봐도 비밀번호는 보이지 않는다.
- 관리자 상태는 그 탭의 세션에만 남고, 탭을 닫으면 다시 보기 전용이 된다.
- 비밀번호 변경은 자물쇠 → `비밀번호 변경`. 마지막 변경일이 표시되고 90일이 지나면 변경을 권한다.
- **한계**: 서버가 없는 단일 HTML이므로 이것은 *편집 잠금*이지 *데이터 보안*이 아니다. 링크를 받은 사람은 보드 내용을 볼 수 있다. 외부에 공개하면 안 되는 화면은 올리지 않는 것을 전제로 쓴다.

## 데이터 저장

저장 위치는 상단 폴더 아이콘(저장 위치)에서 고른다. 로컬 파일 시스템에 자동 동기화하는 저장 방식은 없고, 전부 인터넷(Artifact 링크 또는 서버)에 저장된다 — 저장됐는지 헷갈릴 여지를 없애기 위함이다.

| 위치 | 쓰는 상황 | 동작 |
| --- | --- | --- |
| **Artifact 링크** | 링크만 주고 같이 보기 | `공유 저장`(Ctrl+S) → 링크를 받은 사람이 같은 보드를 본다. 동시 저장이 겹치면 나중 저장이 거절된다 |
| **서버 (Supabase)** | 구글 로그인·회원 권한이 필요한 팀 배포 | [DEPLOY.md](DEPLOY.md) 참고 |
| **JSON 파일** | 백업·복제·전달 | 내보내기/불러오기. 이미지까지 한 파일에 인라인으로 담긴다(저장 위치 자체는 아니고 수동 백업용) |

편집 중 내용은 IndexedDB에 자동 백업되므로 새로고침해도 남는다(공유본보다 최신이면 "저장 안 된 변경 있음"으로 표시).

### 이미지 호스팅(Cloudinary) · URL 일괄 변환

저장 위치 → "이미지 호스팅(Cloudinary)"에서 **Cloud name**과 **Unsigned Upload Preset** 이름만 넣으면 연결된다(Cloudinary 콘솔 → Settings → Upload → Upload presets에서 Signing Mode를 Unsigned로 만든 프리셋). API Key·Secret은 필요 없다 — 브라우저 코드에 넣으면 이 화면에 접근하는 누구나 개발자도구로 꺼내볼 수 있어 쓰지 않는다.

이 설정은 (구글 로그인 커스텀 Supabase 연결 정보와 달리) **문서 자체에 저장**된다. 그래서 한 사람이 설정하고 한 번 저장(공유 저장/서버 저장)해 두면, 다른 사람이 같은 문서를 열었을 때 각자 브라우저에서 다시 연결할 필요 없이 그대로 적용된다.

연결해 두면:
- **서버 저장**을 누를 때마다 **지금 쓰는 호스팅(Cloudinary)에 아직 없는** 화면 이미지·이미지 레이어를 자동으로 올리고 URL로 바꾼 뒤 저장한다(이미 Cloudinary URL인 이미지는 건드리지 않는다). data: 인라인, Supabase Storage 서명 URL, 예전에 다른 곳에 올렸던 URL 등 **Cloudinary가 아닌 것은 전부** 변환 대상이다. 업로드 중에는 진행바가 뜬다.
- 저장 위치 화면의 **"일괄 URL 변환"** 버튼으로도 언제든 같은 방식으로 한꺼번에 바꿀 수 있다(역시 진행바 표시).
- 업로드는 `crm/<연도>-<월>/<보드이름>` 폴더에 담기고, 그 이미지가 속한 페이지 이름이 태그로 붙는다.
- 상단 **앨범** 탭에서 이렇게 올라간 이미지를 태그(페이지)별로 모아 볼 수 있다. Cloudinary 계정 전체를 조회하는 게 아니라 **이 문서에 지금 등록돼 있는 이미지만** 인덱싱하는 방식이라(Admin API는 Secret이 필요해 쓰지 않음), 문서에서 지운 이미지나 앱 밖에서 Cloudinary에 직접 올린 이미지는 앨범에 나타나지 않는다.

**호스팅 업체를 나중에 바꾸려면**: "이미 우리 호스팅에 올라간 URL인가"를 판단하는 지점은 `parts/09-storage.js`의 `isCloudHosted()` 한 곳에 모여 있다(지금은 `res.cloudinary.com` 도메인인지만 확인). 업체를 바꾸면 이 함수와, 그 업체의 업로드 방식에 맞춰 `cloudUpload()`(엔드포인트·응답 파싱)·`cloudFolder()`/`cloudTags()`(폴더·태그 규칙)·`openCloudModal()`(설정 입력 필드)을 함께 고치면 된다. 이 네 곳이 이 앱에서 유일하게 "Cloudinary 고유"인 부분이고, 그 외 로직(어떤 이미지가 변환 대상인지, 진행바, 앨범 등)은 업체와 무관하게 그대로 동작한다.

### 이미지 올리는 방법

| 방법 | 쓰는 상황 |
| --- | --- |
| `화면 일괄 등록` | 여러 장을 선택하거나 폴더에서 가져와 파일명으로 페이지를 자동 매칭한 표를 보여주고 한 번에 등록 |
| 노드의 카메라 버튼 | 페이지를 선택하지 않고 바로 교체 |
| Ctrl+V · 스테이지 드롭 | 선택한 페이지에 등록. 이미 화면이 있으면 이미지 레이어로 얹힘 |

캔버스에 파일을 끌어다 놓는 등록은 없앴다 — 페이지를 옮기는 포인터 드래그와 브라우저의 파일 드래그가 겹쳐 충돌했기 때문. 위 방법들로도 등록 경로는 충분하다.

자동 매칭은 파일명과 페이지 이름·경로를 비교한다. 앞 번호(`01_`, `3-`)와 공백·언더스코어·괄호는 무시하므로 `01_홈.png` → `홈 (비회원)`, `상품 상세.png` → `상품 상세`로 붙는다. 매칭되지 않은 파일은 `+ 새 페이지로 추가`가 기본값이고, 표에서 대상 페이지를 직접 바꾸거나 건너뛸 수 있다. `새로 만든 페이지를 파일 순서대로 연결하기`를 켜면 생성된 페이지들이 화살표로 이어진다.

### 이미지 저장 방식

| 모드 | 이미지 | JSON |
| --- | --- | --- |
| Artifact | `data/img/<노드id>-<시각>.webp` 개별 파일 | 참조 `{ref,w,h}`만 (샘플 기준 8KB 수준) |
| 서버 (Supabase) | Cloudinary 미연결 시 비공개 Storage 버킷에 개별 파일 | 참조 `{path,w,h}`만, 열람 시 서명 URL로 표시 |
| 이미지 호스팅(Cloudinary) 연결 시 | Cloudinary에 개별 파일 | `{url,w,h}`만 — 화면 이미지·이미지 레이어 모두 대상, 서버 저장·Artifact 공유 저장 모두 적용 |
| JSON 내보내기 | data URL로 인라인 | 이미지 포함, 파일 하나로 완결 |

- 업로드 시 최대 1200px·WebP(품질 0.82)로 재인코딩하고, 여정 캔버스용 300px 썸네일만 JSON에 인라인으로 남긴다. 그래서 지도는 이미지 파일을 기다리지 않고 바로 그려진다.
- 화면 이미지를 지우거나 교체하면 쓰이지 않게 된 파일은 다음 저장 때 삭제된다.
- 레이어로 올린 이미지는 640px로 줄여 JSON에 인라인 저장한다(Cloudinary를 연결하면 저장할 때 URL로 바뀐다).

| 태그/캠페인 일괄 업로드 | 태그 목록·캠페인 탭의 `샘플 양식`으로 CSV를 받아 채운 뒤 `일괄 업로드`로 올리기 |
| 삭제 | 선택 후 Delete, 또는 카드의 휴지통 아이콘 |
| 저장 위치 변경 | 상단 폴더 아이콘 → Artifact 공유 저장 / 서버 연결 / JSON 내보내기·불러오기 / 이미지 호스팅 |
